# Applying diagrams and maps to this system

> **TL;DR:** Five concrete, cheap moves ranked by value: a generated Mermaid-plus-legend map of the AI stack, a repo map for the local coding agent, a blueprint library for the 4-bit workers tested on the existing extraction and code-repair evals, DAG-shaped reasoning records on hard tasks, and a quantization sensitivity map emitted by the KL pipeline; each with a pre-registrable test and a stop rule.
> **Source:** Synthesis 2026-11-04 of the diagramming and quantization research against this PC's stack (vault, night-shift runner, evolve-lab, finetune-lab, Ollama workers)  ·  **Project:** AI workstation  ·  **Updated:** 2026-11-04

Ordered by expected value against cost. Each item names the artefact, the test, and the stop rule. None of these needs a new tool with a new role; each extends something that exists.

## 1. A generated system map in the vault (context)

**Artefact.** `Machine/Context/Maps/` with one Mermaid diagram per level (services and timers; repos and data flows; models and who calls them) and a legend table keyed to node ids, generated by a script from `systemctl --user`, the repo list and the AI stack topic page. Front matter with `type: map`, `description`, `sources`, so the index and `ai-notes` pick it up. An `index.md` routes.

**Why.** The AI stack page is prose and tables; agents re-derive the topology every session. A map under 5,000 characters per level is retrievable in one chunk and cheap in tokens.

**Test.** Ten session-start questions ("what runs at 00:30", "which repo feeds the pulse timer") answered by a local model with and without the map in context; score exact-match. Stop if the map does not raise accuracy by 20 points, since then the prose was enough.

## 2. A repo map for the local coding agent (context)

**Artefact.** An Aider-style repo map (tree-sitter symbols, PageRank, token budget) generated per repo and handed to opencode/qwen3.5 as context, through a small script (pyrepomap or a local reimplementation) kept in the AITools scripts folder.

**Test.** The seven code-repair tasks already used in the local model bake-off, with and without the map. Stop if repairs do not improve by at least one task across two runs.

## 3. A blueprint library for the 4-bit workers (scaffold, and the quantization link)

**Artefact.** Five to ten blueprints (step-by-step procedures) for the recurring local jobs: ticker extraction, lead enrichment checks, code repair, summarization with verbatim quotes, diagram generation. Stored as notes with `type: blueprint`, retrieved by task type, placed in the prompt. The large model (Claude) writes and revises them; the small model executes. This is the Blueprints and instruction-retrieval recipe.

**Test (pre-registered).** Run `gemma4:12b` at Q4_K_M and, once experiment 001 picks it, at the best alternative quant, on the 150-item extraction set and the code repairs, with and without the blueprint. Four cells. Hypotheses: blueprints raise the Q4 score; the gain is larger at the lower quant (scaffolds compensate quantization). Stop if the blueprint adds under 0.02 on the extraction score.

## 4. DAG-shaped reasoning records on hard tasks (scaffold and check)

**Artefact.** A response schema for hard tasks: numbered steps with `parents` and `conclusion`, as in DAG-Math; a deterministic checker that rejects dangling steps; a renderer to Mermaid for the owner. Used by the night-shift reviewer and by any evaluation that compares quantizations.

**Test.** On the extraction set, measure how often two quants of the same model produce "logically close" DAGs; compare with their KL. Stop if the DAG format costs more than 30% extra tokens without catching errors the plain format missed.

## 5. A quantization sensitivity map (quantization produces a diagram)

**Artefact.** Extend `kl_report.py` to emit a Mermaid heat-map-style diagram of per-tensor-type sensitivity (from the eight-run plan in the mixed-precision note) with a legend table of mean KL per tensor family, stored next to the experiment note and mirrored to GitHub.

**Test.** None needed; it is an output. Its value is that an agent choosing a `--tensor-type` mix can read it.

## 6. Things deliberately not proposed

- A graph memory product, a multi-agent graph, or a debate topology: the vault's evidence review rejected them.
- Diagrams as images for vision models: slower, lossier, and the gemma4 vision tower is the part we keep at full precision for other reasons.
- llms.txt for the owner's sites: adoption is low and benefit unproven; a sitemap and clean markdown do the same.

## 7. Order and ownership

Item 3 first (it is the only one that tests the quantization link and reuses existing evals), then 1 and 2 (cheap context wins), then 5 when experiment 001 runs, then 4. Each becomes a Paperclip issue when the owner picks it; scripts live in AITools (public, generic) or the repo they serve (private), never in the vault beyond the research folder.
